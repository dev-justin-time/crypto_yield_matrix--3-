## 3. Findings

### FI-001 — Deployment mirror drift (11 `validate.md` + manifest)

**Severity:** Low (cosmetic/docs drift — no code logic affected)
**Status:** Open

**Evidence:** `sync_deployments.py --check` reports 11 `validate.md` copies across `blocks_deploy/*/` that differ from the root `validate.md`, plus the `deployment_mirror_manifest.json` manifest itself is stale. The `validate.md` file was regenerated by `audit_csv.py` (which runs before the sync check), but the mirrors were not updated.

**Root cause:** `audit_csv.py` writes a fresh `validate.md` at the end of its run but does not trigger `sync_deployments.py --write` afterward. The mirror manifest was not regenerated after the last `validate.md` update.

**Fix:** Run `python sync_deployments.py --write` to synchronize all mirrors.
```bash
python sync_deployments.py --write
```

### FI-002 — Duplicate unreachable `except HTTPError` handler in `live_data.py`

**Severity:** Low (dead code — no runtime effect but indicates a copy-paste error)
**Status:** Open
**File:** `live_data.py`, method `LiveDataCollector._blockchain()`, lines ~177-189

**Evidence:** The `_blockchain()` method has two consecutive `except HTTPError as error:` blocks in the same `try` statement. The second block is **unreachable** — Python will always match on the first `except HTTPError` handler. Both blocks assign the same values to the same state fields, so no actual behavioral bug occurs, but the dead code is misleading and the duplication suggests a copy-paste mistake.

**Relevant code (lines ~171-195):**
```python
            except HTTPError as error:                    # <-- First handler (active)
                client.state.last_http_status = int(error.code)
                client.state.last_headers = _safe_rate_headers(error.headers)
                client.state.failures += 1
                client.state.last_error = f"HTTP {error.code}"
                errors.append({"provider": client.state.name, "error": f"HTTP {error.code}"})
            except HTTPError as error:                    # <-- UNREACHABLE
                client.state.last_http_status = int(error.code)
                client.state.last_headers = _safe_rate_headers(error.headers)
                client.state.failures += 1
                client.state.last_error = f"HTTP {error.code}"
                errors.append({"provider": client.state.name, "error": f"HTTP {error.code}"})
            except Exception as error:
                ...
```

**Fix:** Remove the duplicate `except HTTPError` block (the second occurrence).

### FI-003 — `release_gate.py` template produces invalid placeholder values

**Severity:** Low (template only; validation correctly rejects the placeholders)
**Status:** Open
**File:** `release_gate.py`, `template()` function

**Evidence:** The `template()` function initializes all fields to `""` then selectively updates list fields. However `paid_canary_max_approved_spend` (expected: number) and `actual_task_count_and_spend` (expected: object) remain as empty strings `""`. When this template is fed into `release_gate.py --record`, the validator correctly rejects them — but the template itself should contain valid zero-values so an operator can fill only the real evidence fields.

**Expected template values:**
```json
"paid_canary_max_approved_spend": 0,
"actual_task_count_and_spend": {"task_count": 0, "spend_usd": 0}
```

**Fix:** Update `template()` to set these two fields to `0` and `{"task_count": 0, "spend_usd": 0}` respectively.

### FI-004 — `BINANCE_SYMBOLS` coverage gap vs. canonical symbols

**Severity:** Low (live worker limitation — historical data unaffected)
**Status:** Open (product limitation)
**File:** `live_data.py`, `BINANCE_SYMBOLS` dict

**Evidence:** The `BINANCE_SYMBOLS` mapping covers 53 ticker symbols, while the canonical `yield_data.csv` has 59 unique asset symbols. Missing Binance mappings: `SUI`, `APT`, `RENDER`, `TAO`, `XTZ`. These assets cannot receive live price observations from the worker even if they are traded on Binance with USDT pairs.

**Fix:** Add missing Binance USDT ticker symbols: `SUIUSDT`, `APTUSDT`, `RENDERUSDT`, `TAOUSDT`, `XTZUSDT`.

### FI-005 — Gateway budget state not durable across restarts

**Severity:** Medium (financial control — already noted in prior audit)
**Status:** Open (carried forward from `audit.md` CR-003/HI-003)

**Evidence:** The gateway persists budget to `GATEWAY_BUDGET_STATE_FILE` (default `.gateway-budget.json`) and resets daily. However:
- The file is on a single process's filesystem — multiple gateway instances would have independent budgets
- Container restart without a persistent volume loses the budget state
- The `docker-compose.live.yml` has no budget volume mount for the gateway

This was previously identified as CR-003 (horizontal scaling) and is now confirmed to also affect single-instance persistence under restarts.

## 4. Code Quality Observations

### 4.1 Strengths

- **Strong defensive coding:** Common handler (`common.py`) validates context filenames against an explicit allowlist, prevents path traversal, requires `source_file=yield_data.csv`, marks unavailable numeric values as `null` rather than zero, and never makes network calls from paid tasks.
- **Gatekeeper pattern:** `trigger_guarded.py` requires `--live` AND `--confirm-paid` flags plus `BLOCKS_API_KEY` before any paid dispatch. Default mode is no-spend dry-run.
- **Atomic writes:** Both `live_worker.py` and `live_canary.py` use `tempfile + rename` pattern for atomic snapshot writes.
- **Safe budget semantics:** The gateway conservatively reserves budget before dispatch (not after), so failed/canceled tasks still count against the ceiling — preventing overspend from uncertain outcomes.
- **Deterministic builds:** `generate_deployments.py` and `sync_deployments.py` provide hash-verified deterministic mirroring for all 11 data-consuming deployments.
- **LLM hardening:** The gateway's `llm.ts` validates that hosted endpoints resolve to public IPs only (no loopback, private, metadata, or internal addresses), enforces HTTPS, requires configured allowlists, and caps response sizes.

### 4.2 Minor observations

- **`live_data.py:_blockchain()`** uses `ProviderClient.state.wait()` but does not use `get_json()`, bypassing the built-in retry logic. The RPC clients could use `get_json()` with a POST body adapter for consistency.
- **`server.ts`** JSDoc has a formatting glitch: the `POST /llm/chat` line has a leading space and mismatched indentation in the block comment.
- **`release_gate.py`** validation allows `terminal_state` values `"error"` and `"canceled"` in the allowed set but the `trigger_guarded.py` treats non-`"completed"` as an error — minor semantic inconsistency.
- **`run_live_tests.py`** is a standalone test runner (not using `unittest` or `pytest`) — adequate for current scope but would benefit from a standard test framework as the test suite grows.
